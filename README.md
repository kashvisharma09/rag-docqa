# RAG Document QA

A retrieval-augmented question answering system over research papers on Parkinson's tremor detection with wearable IMU sensors. Answers are generated by a local LLM and cite their sources.

## Architecture

PDFs -> chunking (800 chars, 150 overlap) -> embeddings (all-MiniLM-L6-v2) -> ChromaDB -> top-k retrieval -> Llama 3.2 via Ollama -> FastAPI `/ask` endpoint

## Setup

1. Create and activate a venv, then `pip install -r requirements.txt`
2. Install Ollama (ollama.com) and run `ollama pull llama3.2`
3. Put PDFs in `data/raw/`
4. Build the index: `python -m src.embed_store`
5. Ask from the command line: `python -m src.generate`
6. Run the API: `uvicorn src.api:app --reload`, then open http://127.0.0.1:8000/docs

## Evaluation

`python -m eval.run_eval` measures retrieval hit-rate (does a retrieved chunk contain an expected keyword) on 22 questions across 3 papers.

| Chunk size | Overlap | k=2 | k=4 | k=6 |
|---|---|---|---|---|
| 400 | 80 | 64% | 82% | 82% |
| 800 | 150 | 73% | 82% | 82% |
| 1200 | 200 | 68% | 82% | 91% |

Chosen setting: 800/150 with k=4 (82%), which balances retrieval quality and prompt size for a small local model.

## Limitations

- Hit-rate checks keyword presence in retrieved chunks, not answer correctness.
- Small corpus (3 papers) and a 22-question test set, so differences of a few points are not conclusive.
